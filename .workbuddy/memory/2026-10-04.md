## mini-mcp-cesium：MCP → WebSocket → 浏览器 → Cesium 桥接验证项目

路径：`GeoAI/mini-mcp-cesium`，ESM，Node 22。已全部验收通过。

### 架构
- `server.js` 单进程三合一：MCP stdio Server + express 静态服务(3000) + WebSocketServer(3001)
- 4 个工具：`open_page` / `send_code` / `run_code` / `get_status`
- 页面用 `new Function('viewer','Cesium', code)` 执行，暴露 `viewer` 与 `Cesium` 两个变量
- 所有日志走 `console.error`（stdout 属 MCP 协议通道）

### 踩坑与解法（重要，可复用）

1. **MCP SDK 1.32 的 `inputSchema` 必须是 zod schema / raw shape**，传 JSON Schema（`{ type: 'string' }`）直接抛
   `inputSchema must be a Zod schema or raw shape`。需 `npm i zod` 并写 `z.string().min(1)`。

2. **Cesium.js 必须先于 monaco loader.js 加载**（隐蔽坑，无控制台报错）：
   Cesium 产物含 UMD 模块（ipv6），检测全局 `define.amd`；若 Monaco AMD loader 先注入 `define`，
   Cesium 走 `define(t)` 分支被 Monaco 拒绝（`Can only have one anonymous define call per script file`），
   脚本中断 → `window.Cesium` undefined → 地球全黑。
   排查手法：分离 probe 页（同源/非同源、换顺序、换版本）逐步缩小范围，
   同源才能看到真实 `window.onerror` 详情（跨域只给 `Script error.`）。

3. **合规调整**：需求原写 `OpenStreetMapImageryProvider` + `tile.openstreetmap.org`，
   属境外 OSM 直连瓦片，不合规。改为天地图影像 + 显式 key 占位符；
   未配置 key 时退化为纯色地球 + 经纬网 + 大气，桥接链路验证不受影响。

4. **端口占用**：server.js 已加 `EADDRINUSE` 显式报错并退出（原来直接崩栈）。

### 验证结论
`npm test` 走通；`open()` 在 macOS 真实拉起浏览器并自动连入；
页面回执 `"flying-to-oriental-pearl"` 证明代码在 Cesium 中执行成功。

### 环境注意
- Safari 后台标签页 rAF 暂停 → `camera.flyTo` 动画停住（代码已执行，画面不推进）。非代码缺陷。
- 截图无法捕获 WebGL 像素（Safari 后台标签页限制），需前台标签页才能肉眼确认地球。
- **判断 Cesium 是否真的渲染，别看截图**。用 `scene.context._gl.readPixels()` 读 framebuffer 像素，

  曾因只看截图误判为「地球全黑」，实际是相机高度设置问题。

## GeoAI：能力库层（kit）第 1 步落地 —— 已完成

用户拍板：**库要对外发npm** + **Cesium 保持 CDN，库走注入式**。据此只做第 1 步（原地建库），
不动包结构/不动发布，留第 3 步拆 monorepo 待数据验证。

### 关键设计决策

**注入式契约（整个方案的技术支点）**：库内一律 `import` 不到 cesium，
Cesium 只从 `mountKits({ Cesium, viewer })` 入参拿。
→ 同一份库可同时服务「GeoAI 页面 CDN window.Cesium」与「Orillusion Geo npm cesium」，
并从API 契约层面堵死双 Cesium 实例问题（不是靠约定靠类型）。
→ 反推：cesium-extends 内部 `import from 'cesium'`，**不能**直接用作依赖，
只能当「参考源」读源码后重写成注入式。

**三层职责边界**（防漂移）：经验层只存「意图→调哪个库+ 边界条件」，不再存整段代码；
代码只在库里。已同步改写3 条重叠经验条目（lookat-unlock / flyto-moveend / arcgis-world-imagery），
各加一段「已封装为库 + 本条保留的价值是边界条件」。

**三类包处理**：自建=注入式源码；npm 依赖（cesium-extends）=只登记不深链；
script 引入=只登记（全局变量+ 加载顺序敏感，见 README 已知限制 #2），MCP 不保证 run_code 可用。

   只有 core 的同目录 `./` 失败，导致我误判为「import type / bundler 模式 / 文件名冲突 / JSDoc 干扰」，
   连续排查了5轮。用 `tsc --traceResolution` 才看到候选路径是
   `cesium-kit-core/cesium-api-types.ts`（同目录）—— **同目录 ./ 失败但跨目录 ../ 成功时，先怀疑自己路径写错**。

2. **`readonly` 不能修饰方法签名**：interface 里写 `readonly sampleTerrainMostDetailed(...)` 报
   TS1024（readonly 只能用于属性/索引签名），改回普通方法签名。

3. **JSDoc 里的 import 路径会被解析**：注释中写`./xxx.ts` 不影响，但同一文件内
   JSDoc 提到模块名可能干扰 trace 输出的判读，排查时先清掉注释再看日志。

4. **TS 抓出一个真实 bug**（迁移的真正价值）：`ImageryLayer` **没有 `remove()` 方法**，
   我在 JS 版里写 `layer.remove()` 是错的。正确做法是 `viewer.imageryLayers.remove(layer)`，

### 修掉的原库确定性缺陷（重写而非照抄的理由）

drawer：start() 重入泄漏 painter（`_initPainter` 在 status 检查之前）；
once 文档 undefined 实为 true；sameStyle 默认 true 使 dynamicOptions 恒失效；
右键 <3 点 clear 整图；断点样式写死不可配。
measure：destroy() 泄漏整个 drawer；DistanceMeasure.start() 二次调用静默 no-op；
贴地类每次 mousemove 做 100 次 globe.pick；AreaSurfaceMeasure 无 seed 随机点致结果不可复现；
lat1/lon1 取自 point2 的变量错位；单位显示跳变 + 多余空格。
popup/common：自定义 container 时 `viewer.container.removeChild` 必抛 NotFoundError；
destroy 后再 enable 内容翻倍；Occluder 半径硬编码 6350000；destroy 后 postRender 仍回调。

### 关键设计决策

- **measure 是纯函数库，不含交互**（原库把 drawer + 2 个 tooltip 都塞进 Measure），
  交互由 drawer 组合 → 天然无泄漏、无状态机卡死、可重入。
- **drawer 用互斥 `pick: 'ellipsoid'|'terrain'|'model'` 枚举**，
  替代原库两个可同时为true 的布尔（model 优先级更高会静默吞掉 terrain）。
- **overlay 锚点用判别联合 `Anchor`**（kind: 'lonlat' | 'screen'），
  类型上排除「同时传/都不传」，省掉库内分支判断。
- **surface 模式默认 `offViewport:'error'`**：宁可报错提示先 `flyToRegion` 取景，
  也不返回依赖当前视角的数字（原库是非空断言 + NaN 静默传播）。
